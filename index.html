Give it to your AI agent

Connect it as an MCP server

If your AI app supports MCP (Claude, ChatGPT, Cursor, VS Code, Codex and many more), add the search as a set of tools. The app then finds studies, reads their records, looks for similar ones and follows their citations by itself, whenever research would help. Add this address. There is no key and no sign-in:

https://api.sciencemadereadable.com/mcp
Claude Code

In a terminal:

claude mcp add --transport http --scope user science https://api.sciencemadereadable.com/mcp
Codex

In a terminal:

codex mcp add science --url https://api.sciencemadereadable.com/mcp
Claude app and claude.ai

Settings → Connectors → Add custom connector. Name it Science search, paste the address above, and leave the advanced settings empty.

ChatGPT

With developer mode on (in Settings, under Apps), create a new connector: paste the address above and choose no authentication.

Cursor

Add this to ~/.cursor/mcp.json (or .cursor/mcp.json in a project):

{
  "mcpServers": {
    "science": { "url": "https://api.sciencemadereadable.com/mcp" }
  }
}
VS Code

Add this to .vscode/mcp.json in your project, or run MCP: Add Server from the command palette and choose HTTP:

{
  "servers": {
    "science": { "type": "http", "url": "https://api.sciencemadereadable.com/mcp" }
  }
}
Any other app

Add a remote MCP server with the address above. Transport: Streamable HTTP. Authentication: none.

Then just ask, for example: "What does the research say about creatine and memory? Cite the papers."

What your app gets: six tools (search_papers, get_papers, find_similar_papers, citation_walk, map_topic: the research groups inside a topic with every group's reading lists and experts, and read_topic_group: one group in depth, every paper with its abstract), three ready-made prompts (a field overview, a literature review, and checking a claim), and guidance that teaches it to map a field first and read it in full. Every answer has the DOI link to cite. 30 tool calls a minute per address (a topic map counts as 5).

In a chat that can only open links

ChatGPT, Claude, Gemini and other chats that browse but can't run code can search with a plain address: the question goes in the address, the answer comes back as text. Paste this:

To find scientific studies, open https://ask.sciencemadereadable.com/ followed by the question, for example https://ask.sciencemadereadable.com/why%20do%20cats%20purr (add ?k=30 for more results, ?year_from=2020 for recent ones). To learn about a field or topic (or when asked to teach or review one), start instead with https://ask.sciencemadereadable.com/map/ followed by the topic: its research groups and what to read in each. Then read the groups that matter in full, every paper with its abstract: add ?read=N to that address, then ?read=N&part=papers&page=1, 2, and so on. Cite the links it gives.

Try it yourself: ask.sciencemadereadable.com/why do cats purr. Some chats only open addresses that appear in the conversation: then paste the full link with your question in it.

Call it from code

Plain HTTPS and JSON. Click a link to see a real answer in your browser.

B=https://api.sciencemadereadable.com/api/data
curl -G "$B/search" --data-urlencode "q=does intermittent fasting help weight loss" -d k=5 -d abstracts=false
curl -G "$B/search" --data-urlencode 'q="gut microbiome" AND (autism OR ASD) NOT mice' -d k=5
curl "$B/works/10.1126/science.aan8048"
import requests
B = "https://api.sciencemadereadable.com/api/data"
r = requests.get(f"{B}/search", params={"q": "microplastics in human placenta", "k": 20,
                                        "year_from": 2020, "abstracts": "false"}, timeout=30)
r.raise_for_status()
for p in r.json()["results"]:
    print(p["year"], p["citations"], p["title"], p["doi"] or p["openalex"])
/search?q=…Studies by meaning (ask in plain words) or by exact words (quotes, AND, OR, NOT). Filters for years, type, open access. Try ↗
/works/{id}One study's full record, by DOI, OpenAlex id or PubMed Central id. Try ↗
/similar/{id}The studies closest in meaning to one study. Try ↗
/walk?id=…A citation walk: what studies like this one cite that it does not. Good for "what should I read next?". Try ↗
/map/placeWhere studies, or a question, sit on the map of science.

To send a person to a study on this site, link to https://sciencemadereadable.com/?work= followed by its DOI.

Good to know

  • Be gentle: 30 requests (or MCP tool calls) a minute per address (reading the guide doesn't count). Ask for up to 100 results in one search rather than many small ones. Go over and the answer says how many seconds to wait.
  • Need more? Make an account for an API key: 60 requests a minute for your programs wherever they run, free, or 300 a minute with the paid plan. Without a key, nothing changes.
  • What it covers: English titles and abstracts from OpenAlex, not full texts. New papers arrive with each data update, so the very latest may be missing. The guide gives today's exact numbers.
  • Ask like a paper, not like a search box: "effects of dietary interventions on weight loss in adults" finds better studies than "how to lose weight".
  • Judge results yourself: each result has a junk score (likely spam or not research), but a clean score doesn't mean a study is right. Subject labels are often wrong.
  • Privacy: the server's request log includes what was searched, but not who searched it.
  • Study records come from OpenAlex (CC0). The search code is open source (Apache 2.0).

Search results

We search the titles and abstracts of studies, not their full texts. Ask a question and we find studies about the same idea, even when they use other words (125 million studies with an English abstract). Put words in quotes, or use AND, OR, NOT, and we look for those exact words instead (about 200 million).

How it works

Scientific papers are written for other scientists. This page rewrites a whole paper for a curious 14-year-old: in the authors' own voice, keeping every result, number and caveat, but in words anyone can follow.

The rewriting is done by small open models we trained (Qwen 3.5 with 9, 4 and 0.8 billion parameters). They learned from thousands of papers rewritten by frontier AI models. They are small enough to run on a gaming graphics card, and that is where they run: an RTX 3090 in my home. On busy days I can rent a faster one (an Nvidia H100). When many people are reading, a paper may wait in line, and the page says when the GPU is offline.

How good is it? On our test papers, a judge model scored our 9B 7.8 out of 10, a little above GPT-6 Luna (7.5), below Claude Opus (8.5); it costs about half a cent per paper. It still makes mistakes more often than the big models, so check the original before relying on a detail. With your own API key you can compare with six commercial models.

What can I search? About 200 million studies from OpenAlex, the open catalogue of the world's research, by exact words; the 125 million with an English abstract also by meaning (we read your question like the studies). Each study sits on the map of science, near the studies most like it. Your own programs and AI agents can use the same search: here's how.

Which can be made readable? Open-access research articles in PubMed Central under the CC BY licence, which allows republishing an adapted version with credit (about 5 million). Figures and tables are always the original ones. For the others we show what is known and link to the original.

A demo, not a product. We count visits on our own server, without cookies: each visitor is an anonymous code that changes every day, and the counts don't include what you search for. Your search words do pass through our server's technical log, without your address. If our search is down, "Readable only" searches go to Europe PMC instead, straight from your browser. If your browser asks not to be tracked, nothing is counted. Rewrites made by our models are kept so the next reader gets them instantly.
